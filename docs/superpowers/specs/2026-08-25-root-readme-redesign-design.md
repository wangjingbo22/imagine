# 行知旅伴根 README 展示化改版设计

## 目标

将仓库根目录 `README.md` 从成员任务记录改为常见的 GitHub/Gitee 开源 Web 项目首页。读者应在首屏看懂项目名称、用途、当前阶段和主要技术，并能继续查看功能、截图、运行方式、路线图、团队和课程交付物。

本次只调整项目介绍和文档导航，不修改业务代码、接口、测试、部署配置或其他成员的开发文件。

## 受众与写作原则

主要受众依次为：首次访问仓库的老师或同学、需要本地启动项目的开发者、需要核对 Scrum 交付物的评审者。

README 使用中文为主，保留 FastAPI、React、Plan V1、Plan V2 等必要技术名词。首屏面向产品，不出现 PBI/T 编号、个人任务日志和底层状态机细节。所有能力描述必须以已提交稳定版本和可验证证据为准，未完成能力标明阶段，不用宣传性语言掩盖限制。

## 首屏设计

首屏采用常见开源项目的居中展示结构：

1. 项目名：`行知旅伴`，首屏标题不另加英文副标题。
2. 一句话定位：`面向国内城市、支持预算与关怀约束的单日旅行规划 Agent 原型。`
3. 技术徽章：Python 3.11+、FastAPI、React 19、TypeScript、Sprint 1 Beta。
4. 快捷锚点：项目介绍、功能特性、快速开始、路线图、项目文档。
5. 一张经过核验的产品截图。
6. 当前阶段：`Sprint 1 Beta——单人单日核心闭环已接通，真实地图与公网发布仍在完善。`

首屏不使用用户明确删除的文案“从自然语言约束到可执行的 Plan V1 / Plan V2”，也不放团队表、启动命令、PBI 编号或个人姓名。

没有可访问的远端 CI 运行页时，不放 `build passing` 徽章；没有公网 URL 时，不放“在线体验”按钮；没有仓库许可证时，不展示 License 徽章或章节。

## 项目简介与核心功能

项目简介从用户价值出发：用户通过自然语言输入城市、日期、预算、兴趣、地点和关怀需求；系统结合高德地点与路线事实进行确定性约束校验，形成单日计划；执行中记录任务和实际消费，必要时生成候选 Plan V2，并由用户决定是否接受。

核心功能以短列表呈现：

- 自然语言需求与歧义确认
- 普通、亲子、低体力、行动辅助四类关怀画像
- 高德城市、POI、路线距离、时长和来源事实
- 步行、换乘、休息、时间和预算的确定性校验
- 服务端签发并确认 Plan V1
- 开始、完成、跳过和实际消费执行事件
- 单候选 Plan V2、V1/V2 Diff、接受与拒绝
- 计划费用、实际费用、任务状态和版本历史基础总结

首页不宣称高德生成整个旅行计划。统一表述为“高德地点/路线事实 + 行知旅伴服务端确定性规划”。首页不宣称已接入在线大模型；当前定位使用“Agent 原型”。

## 使用流程

README 使用一条简洁流程说明完整体验：

`自然语言需求 → 关怀画像确认 → 高德事实 → 约束/路线/预算校验 → 唯一 Plan V1 → 执行与实际消费 → Plan V2 对比与决策 → 旅行总结`

流程图与架构图优先使用仓库内静态 SVG 或 PNG，避免依赖 Gitee 对 Mermaid 的具体渲染能力。

## 技术架构与快速开始

架构说明保持一屏可读：React 19 + TypeScript + Vite 前端调用 FastAPI；后端连接高德 Web 服务、确定性规划/重规划、PlanVersion 与执行事件服务；Provider 缓存和业务状态落在 SQLite。

快速开始必须同时覆盖后端与前端：

- Python 3.11+，创建 `.venv`，安装 `.[dev]`，从 `.env.example` 创建根 `.env`，启动 `uvicorn app.main:app --reload`。
- Node 22，从 `frontend/.env.example` 创建 `frontend/.env`，执行 `npm ci` 和 `npm run dev`。
- 明确列出 Web、API 和 Swagger 的本地地址。
- 高德 Web Service Key 只放后端根 `.env`，不得写入前端配置或提交 Git。

详细接口和部署配置分别链接到 `frontend/src/api/API.md` 与 `deploy/README.md`。

## 测试与状态口径

README 给出测试命令，不硬编码容易过时的长期承诺。提交 README 前在稳定 `main` 上运行：

- Python 全量测试
- 前端 Node 测试
- TypeScript/Vite 生产构建
- README 相对链接检查

如写入测试数量，必须注明对应提交或“最近一次本地验证”，并与实际输出一致。

当前状态以以下边界展示：

- 已实现：自然语言需求与关怀画像、高德地点/路线事实、确定性 Plan V1、执行事件、实际消费、单候选 Plan V2、Diff、接受/拒绝、基础总结。
- 正在完善：自然语言具体起终点提取、真实地图 Polyline、自主多候选生成、公网 HTTPS 演示地址。
- Sprint 2：2—3 人公平推荐、一次性 GPS 到达辅助、任务照片、迟到/疲劳事件、旅行回忆页。
- Sprint 3：故障降级、三城完整链与两城烟测、多日 Schema、自动化质量门禁、部署和答辩证据。
- 明确不做：持续 GPS、视频剪辑、全国无障碍保证、优惠券/跑腿和第三方批量抓取。
