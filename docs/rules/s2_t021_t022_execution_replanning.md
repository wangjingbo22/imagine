# S2-T021 / S2-T022 执行调整重规划规则

## 1. 权威输入

- 客户端只能提交已确认的 `LATE | FATIGUE` 事件、唯一的锁定任务 ID 和是否请求差异解释。
- `CURRENT`、执行事件、原候选事实、长期关怀约束和费用均由服务端恢复。
- 客户端不得提交候选计划、FactRef 内容、编译后约束、校验状态或 PlanVersion ID。

## 2. S2-T021 确定性重规划

1. 要求父版本是服务端签发的唯一 `CURRENT V1`。
2. 冻结已完成、已跳过、已开始、当前任务和显式锁定任务所覆盖的连续前缀。
3. 从可信事实推导剩余时间、实际消费、步行与休息基线，再由 S2-T020 编译瞬时 HARD 约束。
4. 后缀规划结果必须重新通过预算、时间、路线、关怀四域 HARD 校验及本次瞬时约束。
5. 只有完整可行且最小扰动的候选才允许登记为 `PROPOSED V2`；无解时只返回冲突、规则和可放宽项，V2 与签发记录均为零写入。

S2-T020 约束只存在于本次候选校验与签发证据中，不写回长期画像或 S1-T007 约束。

## 3. S2-T022 Diff 与决策

- 预览同时返回结构化候选、Diff、冻结任务、候选评估、HARD 校验报告和瞬时约束；接受前 `CURRENT` 不变。
- `ACCEPT` 复用既有事务完成 `V1 CURRENT -> SUPERSEDED`、`V2 PROPOSED -> CURRENT`。
- `REJECT` 将 V2 置为 `REJECTED`，原 V1 保持唯一 `CURRENT`。
- 接受和拒绝都要求 V2 具有匹配的服务端 `ISSUED` 记录。

百炼只接收服务端已经冻结的脱敏 Diff 投影并生成一段展示文案。未配置、超时、鉴权失败、非 JSON 或额外字段均降级为 `UNAVAILABLE`；候选和 Diff 不受影响，模型没有计划写入或状态迁移权限。

## 4. 当前外部边界

- 最新基线尚无 S2-T006 具体 FactRef 注册表；当前链路只恢复已经由规划边界签发的 `CandidatePlanRequest`，正式在线备选事实仍需 T006/T009 提供。
- 2—3 人权威 Trip/PlanVersion 链仍由 S2-T005 交付；本模块不虚报多人 E2E。
- S2-T023 页面不在本交付范围，后续直接消费预览与决策接口。
- 疲劳三档阈值和迟到超过剩余窗口的产品口径仍需 PO 冻结。
