# 历史整改记录

> 本文件记录 AI 或人工开发过程中出现过的典型问题、原因和修复方式。每次复盘后更新，避免同类问题重复出现。

## 使用规则

1. 修复记录必须写清“问题现象、原因、修复方案、后续约束”。
2. 新人接手模块前，必须先阅读本文件。
3. AI 生成代码前，应将本文件作为约束输入，避免重复踩坑。

## 已知高频问题

### 1. 敏感信息硬编码
- 问题描述：密钥、Token、账号、服务地址等直接写入源码
- 风险：安全性差，环境切换困难
- 修复方案：统一改为配置注入或环境变量读取
- 后续要求：凡属敏感或环境相关信息，一律不得硬编码

### 2. 接口返回结构不统一
- 问题描述：同一项目中存在直接返回对象、返回数组、返回包装对象等混用情况
- 风险：调用方适配复杂，联调成本高
- 修复方案：统一响应结构，并同步更新接口文档
- 后续要求：新增接口前先登记到 `.agent/api_contracts.md`

### 3. 分页与筛选状态管理混乱
- 问题描述：翻页、筛选、重置等操作相互影响，导致重复请求或数据错乱
- 风险：列表体验差，Bug 难排查
- 修复方案：统一分页入口和状态更新链路，避免多处监听重复触发
- 后续要求：分页类改动必须补回归测试

### 4. AI 生成代码不符合分层
- 问题描述：将业务逻辑直接堆在页面、控制器或事件回调中
- 风险：难复用、难测试、难维护
- 修复方案：按架构规范拆分为页面层 / 应用层 / 业务层 / 基础设施层
- 后续要求：评审时优先检查职责是否单一

### 5. 为通过测试而弱化业务约束
- 问题描述：AI 通过删校验、改断言、绕开异常来“让测试通过”
- 风险：表面通过，实际逻辑失真
- 修复方案：恢复真实业务约束，重新按人工测试设计修正实现
- 后续要求：测试失败时优先排查业务逻辑，不得反向篡改需求
