# 标准 Prompt 模板

> 用途：每次让 AI 参与编码、改 Bug、补测试、重构前，先复制本模板并补全 `{}` 占位符，再发给 AI。  
> 目标：把 `.agent/` 目录中的统一规范稳定注入上下文，减少跨会话失忆、风格漂移、接口不一致和越权生成。

---

## 可直接复制版

```md
请基于以下项目规范完成任务，并严格遵守，不允许跳过约束或擅自补全未定义的业务规则。

# 一、项目上下文
- 项目名称：{待定 / 项目名}
- 技术栈：{待定 / Vue3+SpringBoot3 / ArkTS+ArkUI / Python+LangGraph}
- 模块名称：{模块名}
- 需求背景：{这个功能解决什么问题}

# 二、必须遵守的项目规范
请先阅读并严格遵守以下文件：
- `.agent/architecture.md`
- `.agent/coding_conventions.md`
- `.agent/api_contracts.md`
- `.agent/fixes.md`
- `.agent/forbidden_zones.md`
- `.agent/decisions.md`

要求：
1. 不允许违背架构分层规范。
2. 不允许擅自新增接口字段、修改返回结构、改变状态流转。
3. 不允许直接生成 `.agent/forbidden_zones.md` 中禁飞区的核心实现代码。
4. 必须优先复用现有能力，禁止重复造轮子。
5. 必须结合 `.agent/fixes.md` 避免重复引入历史问题。

# 三、当前任务
- 功能描述：{具体要做什么}
- 涉及范围：{前端页面 / 后端接口 / 服务层 / 数据层 / 测试文件}
- 输入定义：{参数 / 请求体 / 触发条件}
- 输出定义：{返回值 / 页面效果 / 状态变化}
- 异常情况：{参数错误 / 权限不足 / 状态冲突 / 空数据 / 超时等}

# 四、开发约束
1. 先理解任务，再给出实现。
2. 如果缺少关键上下文，只能基于现有契约保守实现，不能擅自发明需求。
3. 测试必须遵守“人工主导”原则：
   - 测试场景、断言逻辑、边界条件以人工提供内容为准
   - AI 只能辅助生成测试代码
4. 若任务涉及接口联调，必须保持字段名、错误码、响应结构一致。
5. 若任务涉及安全、核心业务规则、复杂流程编排，应先判断是否属于禁飞区。
6. 不允许为通过测试而删除校验、放宽约束或绕过异常分支。

# 五、实现要求
请按以下原则完成：
- 先查找现有实现和可复用模块，再决定修改点
- 尽量小范围修改，但要完整覆盖需求
- 保持命名、注释、异常处理风格一致
- 对新增逻辑补充必要校验
- 明确说明是否命中历史整改项

# 六、输出顺序
请严格按以下顺序输出：
1. 需求理解
2. 涉及的规范文件
3. 实现方案
4. 测试代码（如果本次任务允许 AI 辅助生成测试）
5. 实现代码
6. 修改说明
7. 风险与注意事项
8. Commit 建议

# 七、Commit 建议格式
- feat({模块名}): {功能说明}
- fix({模块名}): {修复说明}
- refactor({模块名}): {重构说明}
- test({模块名}): {测试说明}
- docs({模块名}): {文档说明}

# 八、特别提醒
- 如果发现需求、接口、测试设计本身不完整，请先指出缺失项，不要擅自替代人工设计。
- 如果涉及禁飞区，只允许给出分析、外围代码、测试辅助或重构建议，禁止直接生成核心实现。
```

## 常用场景追加语句

### 1. 用于“修 Bug”

在上面模板后追加：

```md
补充要求：
- 先定位根因，再修复，不要只修表象
- 不要引入新的兼容性问题
- 修复后说明触发原因、修复思路、影响范围
```

### 2. 用于“补测试”

```md
补充要求：
- 测试设计思路以人工提供的场景和断言为准
- 先列出覆盖的测试点，再生成测试代码
- 不允许根据实现细节反推“投机型测试”
```

### 3. 用于“重构”

```md
补充要求：
- 不改变对外行为
- 重点优化重复逻辑、命名、分层或可维护性
- 输出中说明重构前后差异和收益
```

### 4. 用于“接口开发”

```md
补充要求：
- 严格遵守 `.agent/api_contracts.md`
- 若接口定义存在空缺，只能标记待确认项，不得私自补字段
- 明确列出请求参数、响应参数、异常码和一致性校验点
```

## 使用说明

1. 复制“可直接复制版”全文。
2. 把所有 `{}` 占位符替换成真实内容。
3. 按任务类型追加“修 Bug / 补测试 / 重构 / 接口开发”补充要求。
4. 再把完整 Prompt 发给 AI。

## 暂时可以不填的项

项目尚未确定时，可以先写：
- 项目名称：`待定`
- 技术栈：`待定`

但以下内容尽量不要空：
- 模块名称
- 功能描述
- 输入定义
- 输出定义
- 异常情况
